## 2. 关键设计决策

- **数据存储**：选用进程内内存字典（非 SQLite），理由是“最小可运行、本地演示”，无需额外依赖或建表；代价是重启即丢失数据，已在 README 与 store 注释中如实说明。线程锁仅保证基本并发安全，未引入数据库事务。
- **状态机约束**：非法状态流转一律返回 HTTP 409 并在 `detail` 中说明当前状态；资源不存在返回 404；入参校验由 pydantic 返回 422。支付重复、未支付订单发起售后、审核前退款、重复审核、拒绝后退款等均被拦截。
- **全额退款**：需求明确只考虑全额退款，因此退款金额恒等于订单金额，退款成功后订单状态同步置为 `REFUNDED` 并记录 `refunded_at`。未做部分退款/优惠券/积分相关任何扩展。
- **ID 与时钟**：订单/售后 id 用 `uuid4`；时间戳统一用 `datetime.now(timezone.utc)`，JSON 序列化输出 ISO8601 带时区。
- **测试方式**：用 FastAPI `TestClient`（基于 httpx）在进程内驱动，不占用真实端口；`autouse` fixture 每个用例前后调用 `store.reset()` 保证隔离。运行用 `python -m pytest` 以把项目根加入 sys.path，使 `from app import app` 可解析。

## 3. 识别到的问题 / 已处理

- **本机 Bash 工具 PATH 损坏**：直接调用 `ls`/`cat` 等均报 `command not found`（shim 脚本 `dirname`/`cd` 失败）。改用 PowerShell 调用指定 Python 解释器，并把命令输出重定向到 UTF-8 文件后由 Read 查看，从而完成测试运行与结果核对。
- **测试弃用警告（非失败）**：`StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2` 以及 anyio `BlockingPortal` 别名弃用。仅为依赖版本提示，不影响功能；11 个用例全部通过（11 passed）。未强制升级，避免引入不兼容。
- **`review` 接口对 `REJECTED/REFUNDED` 状态也返回 409**：当前逻辑要求仅 `PENDING` 可审核，重复审核（含已拒绝后再审）一律 409，符合“审核是一次性动作”的简化假设。

## 4. 不确定之处 / 可能的后续

- **持久化**：内存存储仅适合演示；若评测期望跨进程/重启保留数据，需替换为 SQLite/文件存储。本轮按“最小可运行”未做。
- **真实退款通道**：本服务只在内部把订单标记为已退款，未对接任何第三方支付退款接口（如微信/支付宝）。接口名 `refund` 为“执行系统侧退款记账”。
- **订单与售后的关系约束**：当前允许对同一 `PAID` 订单重复创建多条售后申请（未限制“一个订单只能有一个待处理售后”）。需求未明确要求，本轮保留宽松策略；若需约束可加唯一性校验。
- **金额类型**：用 `float` 存储金额，未使用 `Decimal`，对高精度金额场景存在浮点误差风险；演示足够，生产应改为 `Decimal`。
- **列表接口 `/orders`、`/after-sales`**：需求仅要求“查询订单和售后状态”（按 id），额外提供了列表接口方便手动调试；若希望严格最小可移除。
